## 数值平衡结论（19:00 收工点，无用户干预，300 次采样）

> ⚠️ 本节数字在阶段 1 开发中被**推翻并重算过一次**，下方是接入完整引擎后的真实结果。

| | 均值 | 最低 | <40 占比 |
|---|---|---|---|
| 体力 | 50.5 | 14.0 | 22% |
| 饱腹 | 75.1 | 55.5 | 0% |
| 心情 | 52.5 | 0.0 | 22% |
| 专注 | 29.2 | 0.0 | **74%** |

情绪分布（5 个时段采样）：平静 55% / 发呆 22% / 紧张 10% / 累了 7% / 烦躁 3% / 很开心 3%，触达 7/9 种。
未触达的 `自闭`（需连续 3 次检定失败）与 `情绪波动中`（需单次事件造成 ≥15 波动）是设计上的稀有情绪。

**专注是唯一大概率进危险区的轴，这是有意的**——它是用户需要介入的理由。喝水（T13，专注 +8）是用户触发型，无人照看的生物专注必然下滑，深夜回血 +63 次日恢复。

### 三次修正

1. **饱腹**（阶段 0）：v1.0 下品牌策划 19:00 只剩 23，21:45 归零。饱腹只有"吃饭"一个恢复源却每小时 -6。加入固定午餐 + 新增 T17 下午茶后修复。开发期又发现夜间 -2/h × 9h 导致每天醒来即挨饿，补了 09:30 早饭。
2. **心情**（阶段 0）：初稿工作时段 -3 太轻，模拟出均值 76.3、**从未跌破 60**——`M04 烦躁` 永不触发，"鼓励它"按钮完全无用。
3. **全局下调**（阶段 1，推翻前两次的基准）：**阶段 0 的所有平衡模拟都没有事件层。** 接入 36 条事件后实测，事件净耗为 体力 −16 / 心情 −8 / 专注 −17，19:00 实际落到 35/69/36/14，心情与专注双双触底 0——每只无人照看的生物到傍晚都会崩。据此把工作时段衰减整体下调至 体力 −2 / 饱腹 −5 / 心情 −3 / 专注 −2.5，晚间改为 心情 +3 / 专注 +2。

**教训**：数值不能脱离事件层单独校准，且校准依据应该是**情绪分布**而非单个状态的均值——前者才直接对应"用户能明显感觉到角色有个性"这条成功标准。

## 阶段 1 开发注意

1. **必须新增"事件流"UI 模块**。`copy.json` + `events.json` 里 200+ 条文案是这个产品的全部灵魂，但原策划案 13 节的四个页面模块没有一个能显示它们。这个模块同时解决：承载文案、给用户操作反馈、成为主要截图对象。

2. **操作按钮需补两个**：原 13.4 的 6 个按钮里"喝水/摸鱼"无对应事件（已补 E34/E35），且 E33"你鼓励了它"有事件无按钮。建议最终按钮集：
   `陪它工作 / 提醒吃饭 / 请它喝水 / 让它摸鱼 / 让它休息 / 鼓励它`
   （"安排下一项任务"建议砍掉——需要完整任务队列系统，MVP 性价比最低）

3. **分享卡片是 P0 不是 P2**。模板见 `copy.json > share`。命中 combo 的角色必须在卡片上突出显示 title 和 copy。

4. **`supplied: true` / `isNew: true` 标记**了我补充而非原策划案给定的内容，方便你复核。
